# Trust boundaries

The UI renderer uses allowlisted components and DOM text nodes, never model HTML/JS, `eval`, dynamic imports or model-defined executors. Arithmetic accepts bounded numeric ASTs and four functions. Unknown types, duplicate IDs, excessive nesting, invalid values and unsafe expressions are rejected.

The runtime binds to 127.0.0.1; host/origin checks, a session token and strict same-site cookie prevent foreign web pages from making API calls. Downloads are attachments from verified job directories. CSP blocks remote scripts, arbitrary frames and objects. File previews use browser blobs; PDF frames have an opaque sandbox origin. Uploaded files and saved UI state stay under runtime data, which is not served as a static directory.

Skill imports reject source links, archive links, absolute/traversing archive names, excessive file counts and extracted sizes. GitHub import supports official HTTPS repository URLs. Original source becomes a local snapshot with a SHA-256 digest; modified snapshots must be reimported and approved. Import does not execute source. Instructions in an imported Skill are untrusted content and cannot change runtime policy.

All external execution uses a statically registered interface, argv without a shell, typed parameters, user-visible command preview and expiring single-use approval. Credentials are not inherited through the usual environment variables. Recognized credential parameters are omitted from saved UI/model state and redacted in persisted/public job commands, logs and result records; the exact approved command remains in worker memory. CLI credential values can still appear in OS process tools, and scripts may explicitly write them into output files. Logs, time and exported artifacts are bounded. Active records interrupted by restart become failed records with a recovery message.

**Local execution is not an OS sandbox.** An approved script can still read the user's disk credentials, make network requests, change files outside its working directory and start other processes. Input files can change after approval. Digest checks are not an OS-level immutable-source guarantee. Containers, VMs or an OS policy are necessary for untrusted source. The renderer does not accept arbitrary extension code in this release.

Configured models receive the request, current UI and its state. Do not put secrets in UI fields that are sent to a cloud model. API keys entered in model settings stay in server memory and are not returned or persisted. Runtime uploads, source snapshots, saved inputs and logs can contain private information; keep `.skill2ui` private and delete it when no longer needed. External Skills can print secrets they read; environment filtering cannot redact unknown disk secrets.
